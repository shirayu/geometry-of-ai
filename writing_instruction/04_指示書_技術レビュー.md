# 指示書04：技術的正確性レビューパス

## 目的

数式・技術的主張・論文引用の正確性を、専門家レビューの観点で1章ずつ検証する。本シリーズは「直感重視だが適用条件を明示する」誠実さが売りであり、誤った一般化が1つあるだけで信頼が崩れる。

## 実施方法

- **Phase 2 当初の対象**：確定層（`00.md`〜`07.md`）のみ。草稿層（`08.md`〜`15.md`・`appendix.*.md`）は内容が固まってから実施（`00_洗練計画.md` §1.5 参照）。
- **1セッション1章**。レビュアー（AI または人間の専門家）には対象章＋第0回（記法・前提の基準）＋本指示書を渡す。
- レビュアーは修正せず、**指摘レポートのみ**を出す。修正は著者が判断して行う。
- 指摘には重要度を付ける：**A（誤り：修正必須）/ B（誤解を招く：要改善）/ C（より良い説明がある：任意）**。
- 草稿層のレビューを実施する際は、要注意主張を事前リスト化せずレビュアーが章を読んで自ら洗い出す（`STYLE_GUIDE.md` 保留事項に例示あり）。

## 観点チェックリスト

### 1. 数式の検証

- [ ] すべての等式・近似式を導出または出典と突合。特に近似式は適用条件が本文に明示されているか（例：07の $H \approx -\log\kappa$ は注意事項に条件があるが、本文中の使用箇所すべてで条件を逸脱していないか）。
- [ ] 定数・指数の正誤（例：07の典型帯導出 $r=\sqrt{d-1}\approx\sqrt{d}$、02の直交性の標準偏差 $1/\sqrt{d}$、00の実装ノートの期待値表）。
- [ ] 次元の整合（$\mathbb{S}^{d-1} \subset \mathbb{R}^d$ の使い分け、単体 $\Delta^{K-1}$ の次元）。

### 2. 「仮説」と「事実」の区別

本シリーズは「なぜ高速化するのか（仮説）」（03）のように仮説を仮説と明示する方針を取っている。全章で：

- [ ] 実験的に確立した主張、理論的に証明された主張、著者の解釈・仮説、の3つが文体上区別できているか。
- [ ] 特に要注意の主張（レビュアーは必ず原典と突合すること）：
    - 03: nGPTの高速化要因の説明が原論文（Loshchilov et al., 2024, arXiv:2410.01131）の主張の範囲を超えていないか。
    - 07: Hyperspherical VAE（Davidson et al., 2018）の優位性の記述が「実験的に示した」の範囲か（本文は「有利になりうる」と限定しており良い。この水準が保たれているか）。
    - 07: Nagata et al. (2023, 2025) の主張と本文の「Zipf則の幾何学的正体」の対応。引用論文が実際に本文の主張を支持しているか。
    - 02: Word2Vecのノルムと頻度の関係。実装ノートは「概念実験」と明示しているが、本文の記述が実証済みであるかのように読めないか（Schakel & Wilson, 2015 を引用済み。本文の要約がこの実証研究の主張の範囲を超えていないか突合）。
    - 06: 「Attention＝カーネル法の動的版」という対応の限界（Tsai et al. 2019 等の範囲）。
    - 04: 自然勾配と Adam の関係の記述が過剰な同一視になっていないか。

### 3. 幾何学的厳密性

- [ ] 「多様体」と「リーマン多様体」の区別（00の NOTE で導入済み）が後続章で守られているか。距離・角度を語る箇所で計量の存在が暗黙になっていないか。
- [ ] 「測地線」の語が比喩として使われている箇所と数学的に正確な箇所の区別。
- [ ] 「正規化＝球面への射影」と「球面上の最適化（リーマン最適化）」の混同がないか（03は区別しているが、06・07で緩んでいないか）。
- [ ] 球面解釈が成り立つ条件（06に「球面解釈が成り立つ条件」節あり）が、他章の球面前提の議論と整合しているか。

### 4. 引用の突合

- [ ] 本文中の（著者, 年）がすべて参考文献リストに存在するか（逆も：リストにあって本文未言及の文献は注釈で役割が説明されているか）。括弧は全角・`et al.,` のカンマありで統一（`STYLE_GUIDE.md` 参考文献節、および `変更ログ_用語記法.md` B-2 で確定済み）。
- [ ] 年号・会議名の誤りチェック（例：Kingma & Welling は ICLR 2014 / arXiv 2013。本文表記の整合）。
- [ ] Web検索で原論文のabstractと突合し、本文の要約が原論文の主張と一致するか確認。

### 5. 反例・限界の提示

各章の「限界と注意点」系セクションが、その章の主張に対する最も強い反論をカバーしているか。例：

- 03「ノルムに意味がある場合」：ノルムが有用な実例（信頼度キャリブレーション研究等）が十分挙がっているか。
- 07: 分布埋め込みの計算コスト・実装の難しさが公平に書かれているか。

## 出力

章ごとに `レビュー報告_NN.md`：

```txt
## 指摘 #1 [重要度A]
- 箇所：（見出し名＋引用2行以内）
- 指摘：…
- 根拠：（出典・導出）
- 修正案：…
```

## 注意

- レビュアーが原典にアクセスできない場合、その指摘は「未検証」とラベルし、検証可能な形（論文名・節番号）で残す。
- 文体・表記の指摘はしない（他パスの担当）。
