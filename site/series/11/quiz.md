# 第11回 理解度チェック：異なる空間をつなぐ

## 異なる空間をつなぐ

### Q1. 異種多様体

異なるモダリティを別々の空間として扱う理由はどれか。

```quiz
- 別空間にすると学習が不可能になるから
  R: 対照学習のようにモダリティごとにエンコーダを分けたまま埋め込みを比較する仕組みは実際に成立しており、別空間にすること自体が学習を不可能にするわけではない。
- モダリティには表現空間が存在しないから
  R: テキスト、画像、音声はいずれも高次元空間に埋め込まれた表現を持ち、それぞれ独自の低次元構造を反映した表現空間を持つと考えられる。
- [x]各モダリティの局所構造や時間構造を保つ必要がある
  R: テキストの順序依存や文法構造、画像の空間的隣接関係、音声の時間的連続性はそれぞれ意味を担う固有の構造であり、これを保つために別空間として扱う意義がある。
- 各モダリティは同じ統計構造を持つから
  R: テキストは離散的なトークン列、画像は連続的なピクセル配列、音声は時間方向の連続信号というように、モダリティごとに構造は異なっており、同じ統計構造を持つわけではない。
S: /series/11#モダリティごとの構造的特性
A: 画像の空間的隣接、言語の構文、音声の時間的連続性は異なる。共有空間へ写す場合も、固有構造が取り出しにくくなる可能性を考慮する。
```

### Q2. CLIP（Contrastive Language–Image Pre-training）の対照学習

CLIP（Contrastive Language–Image Pre-training）の基本的な学習目標はどれか。

```quiz
- 画像とテキストを別々の分類器で学習し、関係を使わない
  R: CLIPはテキストエンコーダと画像エンコーダの出力を比較し合う対照学習であり、両者の関係（ペアの対応）を使わずに別々に学習する方式ではない。
- 各画像とテキストを同じ一点へ移す
  R: CLIPが目指すのは正しいペアを近づけ誤ったペアを遠ざけることであり、すべての画像とテキストを区別なく一点に collapse させることは目的ではない。
- ペアの対応を使わず、ノルムを最大化する
  R: CLIPの損失はコサイン類似度に基づく対照学習であり、埋め込みは正規化されるためノルムの最大化自体が学習目標になるわけではない。
- [x]正しいペアを近づけ、誤ったペアを遠ざける
  R: CLIPはテキストと画像のペアデータを用いて、正例ペアの類似度を上げ、バッチ内の負例との相対順位を下げるように学習する。
S: /series/11#対照学習の基本アイデア
A: CLIPは画像エンコーダとテキストエンコーダの出力を比較し、正例ペアの類似度を上げ、バッチ内の負例との順位を下げる。
```

### Q3. CLIPと角度

CLIPの類似度を角度として解釈できる条件はどれか。

```quiz
- 温度を無限大に固定する
  R: 温度はSoftmaxの鋭さを調整するパラメータであり、無限大にすると分布が均一になるだけで、類似度を角度として解釈できるかどうかとは関係しない。
- Valueベクトルを正規化する
  R: CLIPの類似度計算はテキストエンコーダと画像エンコーダの出力（埋め込み）そのものを正規化することで角度の解釈を得ており、Valueベクトルという特定の内部要素だけを正規化する話ではない。
- [x]正規化後の内積を角度として使う
  R: テキストと画像の埋め込みをL2正規化すると内積がコサイン類似度になり、なす角として読めるようになる。
- 正規化せずにノルムを自由に変える
  R: 正規化しなければベクトルのノルムが類似度に影響してしまい、角度としての解釈は成り立たなくなる。
S: /series/11#損失関数の幾何学
A: L2正規化により内積がコサイン類似度になり、球面上の角度として読める。正規化なしではノルムの影響が残る。
```

### Q4. 温度パラメータ

CLIPの温度パラメータを下げると、一般に何が起きるか。

```quiz
- [x]類似度の差が強調され、分布が尖る
  R: 低温では類似度の小さな差が強調され、最も類似度の高いペアに分布が集中する。
- 正例と負例の区別がなくなる
  R: 温度を下げると分布はむしろ尖り、最も類似度の高いペアに集中するため、正例と負例の区別はより明確になる方向に働く。
- 各ペアが同じ重みになる
  R: すべてのペアが等しく扱われるのは高温側の性質であり、低温では類似度の高いペアに重みが集中する。
- 埋め込みの次元が変わる
  R: 温度はSoftmaxの鋭さを制御するスカラーのパラメータであり、埋め込みベクトルの次元数を変える操作ではない。
S: /series/11#温度パラメータの役割
A: 温度はSoftmaxの鋭さを調整する。低温では類似度の小さな差が強調されるが、学習の安定性や負例の扱いとのトレードオフがある。
```

## 共有と分離

### Q5. モダリティギャップ

モダリティギャップとは何か。

```quiz
- [x]共有空間でもモダリティごとに異なる領域へ分布する現象
  R: 学習済みCLIPモデルを調べると、テキスト埋め込みと画像埋め込みは同じ空間内でも異なる領域に分布しており、これがモダリティギャップと呼ばれる。
- 画像とテキストを同じデータとして保存できないこと
  R: モダリティギャップは学習後の埋め込みの分布の偏りを指す現象であり、データの保存形式が共通化できるかどうかとは別の話である。
- モダリティ間の次元数が異なること
  R: CLIPではテキストと画像の埋め込みは同じ次元数の共有空間に写像されており、次元数の違いを指す概念ではない。
- 各モダリティが同じ一点へ収束すること
  R: モダリティギャップはむしろ逆に、テキストと画像の埋め込みが同じ空間内でも分離した領域に分布する現象であり、一点への収束を指すものではない。
S: /series/11#モダリティギャップ
A: 共有空間への射影は、単一の滑らかな分布や完全な混合を保証しない。モダリティごとの領域分離が残ることをモダリティギャップと呼ぶ。
```

### Q6. FEDA（Frustratingly Easy Domain Adaptation）

FEDA（Frustratingly Easy Domain Adaptation、驚くほど簡単なドメイン適応）の幾何学的な設計はどれか。

```quiz
- 各ドメインを同じ一点へ押し込む
  R: FEDAは特徴量を3倍の次元へ拡張し共通ブロックと固有ブロックへ分ける設計であり、各ドメインを一点へ押し込む操作ではない。
- 入力特徴を低次元へ圧縮する
  R: FEDAは元のd次元の特徴量を3d次元へ拡張する手法であり、低次元への圧縮とは逆の操作を行う。
- [x]共通特徴と固有特徴を別ブロックへ配置する
  R: FEDAは特徴量を共通ブロックとソース・ターゲットそれぞれの固有ブロックへ分けて配置し、共通の性質と個別の性質を幾何学的に分離する。
- ドメイン固有情報をそのまま削除する
  R: FEDAはドメイン固有の情報を削除するのではなく、専用のブロックへ「逃がす」ことでモデルが活用できる形で保持する。
S: /series/11#幾何学的な本質-次元の直交化
A: FEDAは特徴を共通ブロックとソース・ターゲット固有ブロックへ分ける。次元は増えるが、固有情報の棲み分けを明示できる。
```

### Q7. 共有か分離か

CLIP型の共有空間とFEDA型の拡張について、妥当な評価はどれか。

```quiz
- [x]共有空間は横断検索、分離は固有構造の保持に向くが、選択はタスクに依存する
<!-- quiz-lint-ignore: hedge - 設問が「妥当な評価」を求めており、両手法の得意領域を対比しつつタスク依存を明示するのが正確な答えのため -->
  R: CLIP型は共通概念の抽出に強く検索や横断比較に向く一方、FEDA型は固有構造の干渉を避けられるため、どちらが優れているかはタスクとデータ次第である。
- 共有空間は共通概念の抽出に強いが、固有構造が干渉しやすいので分離を選ぶべきである
  R: 共有空間が共通概念の抽出に強く固有構造が干渉しやすいという評価自体は妥当だが、そこから常に分離を選ぶべきだと断定するのは、タスクによって適切な設計が変わるという前提と整合しない。
- 分離すればモダリティ間の対応を学習できない
  R: FEDA型の分離は共通ブロックを残す設計であり、共通軸を通じてドメイン間の対応を学習できなくなるわけではない。
- 両者は同じ空間操作なので区別できない
  R: CLIP型は異なる多様体を強引に重ね合わせる操作であり、FEDA型は空間を広げて固有構造を別次元へ分離する操作であって、幾何学的な操作としては異なる。
S: /series/11#clipとの対比-「共有」か「分離」か
A: 共有空間はモダリティ横断の比較を容易にする一方、固有構造を圧縮する可能性がある。空間を拡張して分離する設計にも次元増加の代償があり、目的に応じた選択が必要である。
```

### Q8. ImageBindと統合の質

共有空間で画像とテキストの検索は改善したが、音声の分類と画像内の細かな構造は悪化した。統合の評価として、最も適切なものはどれか。

```quiz
- ノルムを揃えれば、モダリティ間の表現差も解消したとみなす
  R: ノルムを揃える正規化は角度としての類似度を成立させる操作にすぎず、モダリティ固有の構造が保たれているかという別の問題を解消するものではない。
- [x]共有対応と固有構造・下流性能を分けて評価する
  R: 複数のモダリティを同じ空間に埋め込むことと意味的に同じ構造を持つことは異なるため、共有対応の質とモダリティ固有の構造の保持、目的別の下流性能を分けて測る必要がある。
- 埋め込み次元を増やせば、固有構造の損失も性能へ反映されないとみなす
  R: 埋め込み次元を増やすことと、音声分類や画像の細かな構造という下流性能に固有構造の損失が反映されるかどうかは別の問題であり、次元を増やせば反映されなくなるとは言えない。
- 共有検索の指標を残し、音声と画像の評価を外す
  R: 画像とテキストの検索が改善する一方で音声分類や画像の細部が悪化しているという事実こそ評価すべき情報であり、その指標を外してしまうと統合の質を正しく判断できなくなる。
S: /series/11#共有空間の質を問う
A: 共有空間での整列は統合の一側面にすぎない。モダリティ固有の構造が保たれているかと、目的別の下流性能を分けて測る必要がある。
```
