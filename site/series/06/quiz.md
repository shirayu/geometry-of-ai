# 第6回: Transformerという測量士: 動的な接続（理解度チェック）

## 動的な空間

### Q1. Transformerの構成

Transformerを構成する要素の組み合わせとして、適切なものはどれか。

```quiz
- [x]Attention、位置情報、Feed-Forward層などを組み合わせる
  R: トークン埋め込みと位置埋め込み、Multi-Head Attention、FFN、残差接続、正規化、出力層が積み重なって一つのブロックを構成しており、単一の部品だけでは動かない。
- 各トークンを独立に分類し、位置情報は入力順から暗黙に得る
  R: Self-Attentionは入力の順序を区別しないため、位置情報は入力順から自動的に得られるわけではなく、位置埋め込みとして明示的に付与する必要がある。
- 入力を固定特徴へ射影し、トークン間の相互作用を使わない
  R: Multi-Head Attentionはトークン間の関係を動的に計算する仕組みであり、固定特徴への一度きりの射影ではなくトークン間の相互作用そのものが中心的な役割を担う。
- 畳み込みで系列の位置関係と長距離依存を表す
  R: 構成要素は畳み込みではなくAttentionと位置埋め込みであり、畳み込み層はTransformerの基本構成には含まれない。
S: /series/06#構成要素
A: TransformerはAttentionによるトークン間の相互作用に、位置情報、非線形変換、残差接続、正規化を組み合わせる。単一の部品だけで動くモデルではない。
```

### Q2. カーネル法とAttentionの使い分け

カーネル法とAttentionの選択について、適用条件に関する判断として最も適切なものはどれか。

```quiz
- カーネル法は入力に応じて類似度を動的に調整し、Attentionは固定された地図を使う
  R: 動的・固定の関係が逆になっている。カーネル関数の形はデータを見る前に決まっており固定的で、Attentionこそ入力に応じて重みを動的に変える側である。
- [x]カーネル法はデータを見る前に類似度の構造が固定される一方、Attentionは入力依存で重みを変えるため、動的な関係が必要なタスクかで選ぶ
<!-- quiz-lint-ignore: length - 両手法の性質と選択基準を対比して正確に述べるため正解が長くなるのが必然 -->
  R: カーネル関数の形はデータを見る前に決まり特徴空間の構造は入力に依存しないのに対し、AttentionはQueryとKeyから入力ごとの重みを計算するため、固定的な類似度で足りるか動的な関係が必要かで選択が変わる。
- Attentionは事前に設計されたカーネル関数を使い、固定された特徴空間に向く手法である
  R: 事前に設計された固定のカーネル関数を使うのはカーネル法の側であり、AttentionはQuery-Keyから重みを学習し入力ごとに関係を構成する手法である。
- カーネル法は入力ごとに異なる関数形を学習するため、Attentionより柔軟に関係を変えられる
  R: カーネル関数の形はデータを見る前に決まっており、入力ごとに関数形を学習して変えるわけではない。柔軟に入力依存の重みを変えるのはAttentionの側である。
S: /series/06#固定性という制約
A: カーネル関数の形はデータを見る前に決まり、特徴空間の構造は入力に依存しない。AttentionはQueryとKeyから入力ごとの重みを計算し、関係そのものを動的に構成する。固定的な類似度で足りるか、入力ごとに変わりうる関係が必要かで、選択が変わる。
```

### Q3. Query・Key・Value

Scaled Dot-Product AttentionにおけるQuery、Key、Valueの役割として正しいものはどれか。

```quiz
- Keyが出力を直接生成し、Valueは使わない
  R: 出力を生成するのはValueの加重和であり、Keyは重みを決めるための整合度計算に使われるだけで、出力の内容そのものを直接生成するわけではない。
- QueryとValueの距離でKeyを更新する
  R: 重みを作るのはQueryとKeyの整合度であり、Keyは学習された射影で決まるものであって、QueryとValueの距離によって更新される仕組みではない。
- 三つは同じベクトルでなければならない
  R: Query、Key、Valueはそれぞれ異なる学習された重み行列で入力から射影されるため、同じベクトルである必要はない。
- [x]Query-Keyで重みを作り、Valueを加重集約する
  R: Queryは何を知りたいかを表し、Keyは各基準点の特徴を表す。両者の整合度をSoftmaxで重みに変換し、その重みでValueを加重集約する構造になっている。
S: /series/06#query-key-valueの直感
A: Queryは何を探すか、Keyは何に反応するか、Valueは取り出す内容に対応する。Query-Keyの類似度をSoftmaxで重みにし、Valueを集約する。
```

### Q4. 球面解釈の条件

Attentionを球面上の角度中心の計算として解釈するとき、必要な注意はどれか。

```quiz
- Valueを正規化すればQuery・Keyの内積も角度に揃うため、Query・Key側の確認は省略できる
  R: 内積が純粋な角度情報になる条件はQueryとKeyの各行ベクトルが単位ノルムに正規化されていることであり、Valueの正規化とは無関係である。
- 内積は正規化の有無にかかわらず角度を表すので、条件確認は省略できる
  R: 正規化されていないQueryとKeyの内積には方向と大きさの両方が混ざっており、常に角度だけを表すわけではないため、正規化の有無を確認する必要がある。
- Softmaxの温度を上げれば、非正規化の内積でも角度解釈に近づく
  R: Softmaxの温度は分布の鋭さを調整するものであり、内積自体に含まれるノルムの影響を取り除いて角度情報に近づけるものではない。
- [x]Query・Keyの正規化とスケールを確認する
  R: QueryとKeyの各行ベクトルが単位ノルムに正規化されている場合に限り内積は純粋な角度情報になるため、球面解釈が成り立つかどうかは正規化とスケールを確認して初めて判断できる。
S: /series/06#球面解釈が成り立つ条件
A: 正規化されたQueryとKeyの内積はコサイン類似度になり、角度として解釈しやすい。非正規化の内積にはノルムの影響が残るため、条件の確認が必要である。
```

## 複数の視点と位置

### Q5. Multi-head Attention

Multi-head Attentionの意義として、適切な説明はどれか。

```quiz
- [x]異なる射影空間の関係を並列に捉え、統合する
  R: 各ヘッドは異なる射影行列を持ち、高次元空間を異なる部分空間に射影してそれぞれAttentionを計算するため、複数の関係を並行して捉えて出力を統合できる。
- 一つのAttentionを同じ入力に何度も繰り返し、視点は増やさない
  R: 各ヘッドは異なる射影行列 $W_Q^i, W_K^i, W_V^i$ を持ち別々の部分空間に射影するため、同じ計算の単純な繰り返しではなく異なる視点を生み出す。
- 各ヘッドは同じ部分空間を担当する
  R: 各ヘッドは異なる射影行列によって異なる部分空間に射影されるため、同じ部分空間を担当するわけではない。
- ヘッドを増やすとトークンの順序情報が得られる
  R: 順序情報を与えるのは位置埋め込みの役割であり、ヘッドの数を増やすことは異なる関係を並列に捉える表現力の向上に関わるものであって、順序情報の獲得とは別の話である。
S: /series/06#multi-head-attention-複数の視点
A: 各ヘッドは異なる射影空間でAttentionを計算できる。複数の関係や特徴の見方を並行して持ち、出力を統合する仕組みである。
```

### Q6. RoPE（Rotary Position Embedding、回転位置埋め込み）

RoPE（Rotary Position Embedding、回転位置埋め込み）が位置情報を表現する方法として、正しいものはどれか。

```quiz
- 各位置を同じ角度で回転させる
  R: 回転行列 $R_m$ は位置 $m$ に依存し、位置ごとに異なる角度で回転させる仕組みであり、すべての位置を同じ角度で回転させるわけではない。
- 位置情報をValueに追加し、QueryとKeyには与えない
  R: RoPEはQueryとKeyのベクトルに位置依存の回転行列を適用する仕組みであり、Valueではなく QueryとKeyの側に位置情報を与える。
- 各トークンへ独立な乱数を加えて位置を表す
  R: RoPEは乱数ではなく位置に応じて決まる回転行列を用いており、回転後の内積を計算すると相対オフセットだけが規則的に残る設計になっている。
- [x]Query・Keyを位置ごとに回転し、相対位置を内積へ反映する
  R: QueryとKeyに位置依存の回転行列を適用すると、回転適用後の内積は符号付き相対オフセットのみに依存する形になり、相対位置が反映される。
S: /series/06#ropeの仕組み-回転による相対位置
A: RoPEは位置に応じた回転をQueryとKeyへ適用する。内積では回転角の差が現れるため、相対位置を扱いやすく、回転はノルムも保存する。
```

### Q7. Attentionのスケーリング

Scaled Dot-Product Attentionで内積をキー次元の平方根で割る理由はどれか。

```quiz
- Valueのノルムを0にし、集約結果の大きさを消す
  R: 平方根で割る操作はQueryとKeyの内積のスケールを調整するものであり、Valueのノルムを操作するものではない。
- 位置情報を削除し、内容トークンを比較する
  R: スケーリングは内積の分散を安定させるための操作であり、位置情報の削除とは無関係である。位置情報は位置埋め込みやRoPEで別途扱われる。
- [x]内積のスケールを調整し、Softmaxの尖りを抑える
  R: $d_k$ が大きいと内積の値も大きくなりやすくSoftmaxが極端に鋭くなるため、平方根で割ることで次元に関わらず内積のスケールを揃え、鋭さを抑える。
- QueryとKeyの次元を1に縮約し、内積計算を軽くする
  R: 平方根で割る操作はQueryとKeyの内積の値を調整するスカラー演算であり、QueryやKeyのベクトル自体の次元を縮約するものではない。
S: /series/06#attentionにおけるスケーリング
A: 内積は次元が増えるとスケールが大きくなりやすい。平方根で割ることでSoftmaxの入力を扱いやすい範囲に保ち、勾配の極端な飽和を抑える。
```

### Q8. 連続と離散の橋渡し

あるAttentionヘッドの重みが複数トークンへ広がっている。出力の意味を確認する説明として、最も適切なものはどれか。

```quiz
- 重みが広がるほど、最も大きいValue以外の情報は無視される
  R: Softmaxは類似度を総和1の重みへ変換するが、低温でない限り複数のValueが寄与するため、重みが広がっている状況ではむしろ多くのValueが出力に影響する。
- 加重和の結果からは、参照したトークンの情報を解釈できない
  R: 出力はAttention重みで各トークンのValueを加重集約したものであり、どのトークンにどれだけの重みが割り当てられたかを見ることで参照元の寄与を追跡できる。
- 重みが確率になるため、出力は入力Valueの一つと一致する
  R: Softmaxによって重みは確率になるが、出力は重み付き集約であり、低温でない限り複数のValueが混ざるため入力Valueのどれか一つと一致するとは限らない。
- [x]類似度を重みに変え、複数のValueを文脈に応じて集約する
  R: Softmaxは類似度を総和1の重みへ変換し、その重みで複数のValueを加重集約する。出力は入力のコピーではなく文脈に応じた集約結果である。
S: /series/06#softmaxの役割-連続から離散への橋渡し
A: Softmaxは類似度を総和1の重みへ変換するが、低温でない限り複数のValueが寄与する。出力は入力のコピーではなく、重み付き集約である。
```
