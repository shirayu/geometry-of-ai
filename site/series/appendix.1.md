## 本Appendixの位置づけ

重みを32ビットの浮動小数点数から2ビット、1ビットへと削っていっても、モデルはそれなりに動く。この事実は、慣れてしまえばなんでもないが、最初に聞いたときは奇妙に響く。連続的に変化する量として学習されたはずのパラメータが、ほとんど二値・三値の離散集合に押し込められて、なお破綻しない。**モデルの量子化（Quantization）を幾何学的視点から考察する**本Appendixが出発点に置くのは、この奇妙さである。

「重みを極端に離散化すると多様体の形状にどう影響するか」という問いは、2024年以降の1-bit/2-bit LLM研究の広がりとともに、実務・理論の両面で重要性を増している。本Appendixでは後述するSTEによる勾配近似を扱い、[第13回](13.md)「スパース性の幾何学」ではパラメータの疎性を扱った。量子化はその延長線上にあるが、扱う離散化の程度が桁違いに大きい。連続空間を格子に切り詰めるという操作が、多様体という幾何学的対象に何をするのか。崩れ方の不均一さまで含めて追っていく。

前提として、[第2回](02.md)（ノルムの呪い）、[第3回](03.md)（球面多様体とnGPT）、[第7回](07.md)（不確実性の表現）、[第13回](13.md)（スパース性とMoE）、[第14回](14.md)（パーシステントホモロジー）の内容に触れる。未読でも読み進められるよう都度補足するが、事前に目を通しておくと理解が深まる。

## 量子化とは何か

### 基本概念

量子化とは、ニューラルネットワークの重み（およびアクティベーション）を、より少ないビット数で表現する技術である（[Jacob et al., 2018](#ref-jacob2018)）。言葉にすればそれだけだが、下の表を並べて見ると刻み幅の落差に気づく。FP32からINT4への移動は、単なる「少し粗くする」ではない。約43億通りの値の候補から16通りへの移動であり、桁が違う。

| 精度 | ビット数 | 表現（概算） | 用途 |
| --- | --- | --- | --- |
| FP32 | 32 | 2^32 通りのビットパターン | 学習時の標準 |
| FP16/BF16 | 16 | 2^16 通りのビットパターン | 学習と推論の高速化 |
| INT8 | 8 | 256段階 | 推論の効率化 |
| INT4 | 4 | 16段階 | 軽量化（GPTQ, AWQ等） |
| INT2 | 2 | 4段階 | 極端な軽量化 |
| 1-bit | 1 | 2段階（例: ±1） | BitNet等の研究 |

> [!NOTE]
> 浮動小数点（FP32/FP16/BF16）の「通り数」は**値の一様な刻み**ではない（指数部を持つため間隔は非一様）。また NaN/Inf/非正規化数なども含まれるため、ここでは「ビットパターン数の規模感」として扱う。

### なぜ量子化が必要か

これだけ荒っぽい削減を行ってでも量子化が求められる理由は、モデルの規模そのものにある。

- **メモリ削減:** LLMのパラメータ数は数十億～数千億。FP16→INT4で概ね約4倍のメモリ削減
- **推論高速化（条件付き）:** 量子化により計算や転送のボトルネックが軽くなることで高速化が期待できる
- **エッジデバイス展開:** スマートフォンやIoT機器での実行を可能に
- **環境負荷軽減:** 計算コストと消費電力の削減

> [!CAUTION]
> 「整数演算は常に浮動小数点より速い」とは限らない。実際の速度は **(a)メモリ帯域律速か計算律速か**, **(b)GPU/CPU/アクセラレータの対応カーネル**, **(c)Tensor Core等の対応**, **(d)量子化形式（W4A16, W8A8, KV cacheの扱い）** に強く依存する。

## 量子化の幾何学的解釈

### 重み空間の「格子化」

ビット数の表だけを見ていると量子化は数値表現の問題に見える。しかし幾何学的に見ると、様相が変わる。**連続的な重み空間を離散的な格子点に制限する**操作であり、空間そのものの姿を変える操作である。

```txt
連続空間（FP32）
↑
  │   .  .
  │  .  .  .
  │   .  .
  └─────────→
  （任意の点を取れる）
  ```

```txt
量子化後（INT4）
↑
  │  ●──●──●──●
  │  │  │  │  │
  │  ●──●──●──●
  │  │  │  │  │
  └─────────→
  （格子点のみ許容）
```

**幾何学的含意:**

- 元の重み $w$ は、最近傍の格子点 $\hat{w}$ に「丸められる」
- これは**重み空間における射影**と見なせる
- 量子化誤差 $\epsilon = w - \hat{w}$ は、この射影による「ずれ」

この射影は、重み一つ一つに独立にかかる。ある重みは格子点にほぼ乗っていて、ずれはごくわずかで済む。別の重みは格子点の中間にいて、大きく引きずられる。丸めの影響は重みごとに異なり、その不揃いさが、次に見る決定境界の形にそのまま持ち越される。

### 決定境界への影響

ニューラルネットワークの決定境界（入力空間をクラスに分割する曲面）は、重みによって定まる。重みが格子点へ寄せられるなら、境界も同じように寄せられるはずだ。実際にどう動くのか。

**直感的理解:**

```txt
量子化前: 柔軟な境界
       ~~~~~~~~~~~~
    A /            \ A
     /      B       \
~~~~~                ~~~~~

量子化後: 硬直した境界
       ____________
    A |            | A
      |      B     |
______|            |______
```

図だけ見ると、境界がここまで角ばって性能を保てるとは思えない。ところが実際には、4-bit程度まで削っても平均的な性能はさほど落ちない場合が多いと報告されている（[Banner et al., 2019](#ref-banner2019)）。

**実務上よく観察される傾向（ただし条件付き）:**

- 適切なPTQ（例: GPTQ/AWQ/SmoothQuant 等）を用いると、**4-bit程度でも性能劣化が限定的**なケースが多い
- 背景には **過剰パラメータ化**や**冗長性**、分布の「鈍感さ」（平均的入力では誤差が相殺されやすい）がある

平均性能が保たれるなら、量子化はいくらでも進められそうに思える。しかし平均という指標は、崩れ方が均一であることを保証しない。

**ただし例外も重要:**

- **1–2 bit級**では表現力制約が強く、劣化が顕著になりやすい
- **稀な入力パターン**、**長文依存**、**微妙な差分判定（ツール呼び出し、厳密な形式出力など）**では、平均性能が保たれても破綻が出ることがある
- 崩れ方は **量子化方式（per-channel / group-wise / スケール推定）** と **キャリブレーションデータ**に強く依存する

つまり量子化の代償は、多数派の入力にはほとんど現れず、少数派の入力に集中して現れる。平均だけを見ている限り、この偏りは見えない。

### 多様体仮説との接続

決定境界の話は、重みという一つの空間の中で完結していた。もう一段視点を引き上げると、量子化が触れているのはデータ側の構造でもあることが見えてくる。深層学習の**多様体仮説**によれば、高次元の入力データは実際には低次元の多様体上（またはその近傍）に分布している。重みを格子化したとき、この多様体はどうなるか。

**量子化と多様体の関係:**

1. **データ多様体への射影精度:**

   - 量子化されたネットワークも、データ多様体を十分に近似できるか？
   - 多くの設定で「概ねYes」になりうるが、**量子化方式、精度、キャリブレーション**に強く依存する

2. **表現多様体の変形:**

   - 中間層の表現は、ある多様体上に分布しているとみなせる
   - 量子化により、この多様体が「ピクセル化」される（局所的な分解能が落ちる）
   - ただし位相的性質（連結性、穴の数等）が保存されるかは、層、タスク、精度で異なる（「保存されがち」だが保証はない）

3. **[第14回](14.md)（TDA）との接続:**

   - パーシステントホモロジーで量子化前後の表現を比較
   - トポロジー的特徴が十分に保たれていれば、量子化は「安全」と言える可能性がある

三つとも、答えは「場合による」で止まっている。位相的性質が保たれるかどうかが層やタスクに依存するという一点だけは、はっきりしている。逆に言えば、量子化の影響は多様体上で一様には出ない。次に見るのは、多様体の形が最初から限定されている場合である。

### 球面上の量子化（nGPTとの接続）

[第3回](03.md)で扱ったnGPTでは、表現は球面上に制約されていた。自由な高次元空間ではなく、ノルム1という束縛の下にある多様体である。量子化はこの制約の上で起きることになる。

**球面上の格子:**

- 球面上に均等に点を配置する問題は、古典的な**球面符号化問題**
- 高次元球面では、点の配置がさらに難しくなる（「等間隔」が直感通りに作れない）

平面の格子であれば直交座標をそのまま刻めばよかった。球面ではそうはいかない。等間隔に見える格子を高次元球面上に敷き詰めること自体が、符号理論の未解決問題の一角を占めている。だとすれば、ユークリッド空間の量子化手法をそのまま球面に持ち込んだとき、何が起こるか。

**具体的な考察:**

- 正規化された表現を量子化すると、ノルム1の制約が崩れる可能性
- 対策1: 量子化後に再正規化
- 対策2: 球面上で直接量子化（研究段階）

対策1は素朴だが効く。量子化で崩れたノルムを、もう一度割り戻すだけである。次のコードは、その往復を最小構成で確かめたものだ。

```appendix1_spherical_quantization.py
import torch
import torch.nn.functional as F


def quantize(tensor, num_bits=4):
    """[-1, 1]の範囲を仮定した対称一様量子化（最小構成）。"""
    levels = 2**num_bits - 1
    scaled = torch.round((tensor.clamp(-1, 1) + 1) / 2 * levels)
    return scaled / levels * 2 - 1


# 概念的なコード
x = torch.randn(2, 3)
x_normalized = F.normalize(x, dim=-1)  # ノルム1に正規化
x_quantized = quantize(x_normalized)  # 量子化
# この時点で ||x_quantized|| ≠ 1 の可能性
x_renormalized = F.normalize(x_quantized, dim=-1)  # 再正規化
```

## 量子化手法の分類と幾何学的特徴

量子化は一枚岩の操作ではない（[Nagel et al., 2021](#ref-nagel2021)）。いつ・どこで丸めるかによって手法が枝分かれし、幾何学的な振る舞いも変わる。

### Post-Training Quantization (PTQ)

学習済みモデルを事後的に量子化する手法。最も素朴な発想は、単に最近傍の格子点へ丸めることだが、これをそのまま適用すると誤差が層を通じて蓄積する。表の下三つは、その蓄積をどう抑えるかの工夫だと見ることができる。

| 手法 | 特徴 | 幾何学的解釈 |
| --- | --- | --- |
| Round-to-Nearest | 最近傍の格子点に丸め | 最短距離射影 |
| GPTQ（[Frantar et al., 2023](#ref-frantar2023)） | 量子化誤差を後続層で補正 | 誤差の伝播を抑える射影 |
| AWQ（[Lin et al., 2024](#ref-lin2024)） | 重要な重みを高精度で保持 | 非一様な格子（重要領域は細かく） |
| SmoothQuant（[Xiao et al., 2023](#ref-xiao2023)） | アクティベーションと重みの分散を均等化 | 空間の「座標変換」後に量子化 |

### Quantization-Aware Training (QAT)

PTQは学習後に格子を当てはめる。QATは、格子があることを学習の段階から織り込む手法である。ここで問題になるのは、丸め操作 $\text{round}(\cdot)$ が至るところで勾配ゼロという、学習に不都合な性質を持つことだ。

**Straight-Through Estimator (STE) の再登場:**

STEの仕組みは単純である。forward計算では $\text{round}(x)$ をそのまま使うが、backward計算ではこの関数の勾配（ほぼ至るところ0）を無視し、代わりに恒等関数の勾配（常に1）で代用する。つまり $\partial \, \text{round}(x) / \partial x \approx 1$ という近似を意図的に導入する。

- STEがここでも活躍（[Hubara et al., 2018](#ref-hubara2018)）
- Forward: 量子化された重みを使用
- Backward: 連続的な勾配を伝播（丸め操作を素通りさせる）
- **幾何学的解釈:** 「見かけは格子点にいるが、勾配は連続空間から来る」

forwardとbackwardで別の空間を使うという、この一見都合のよいごまかしが実際に学習を回せてしまう。離散と連続の境界がどこまで妥協を許すかは、上で見た通りである。

### 極端な量子化（1-bit / 2-bit）

1-bit、2-bitと進むと、格子はもはや「細かい」「粗い」の程度問題ではなくなる。重みが取れる値そのものが数個しかない。

**BitNet（Microsoft, 2023-2024）:**

- 重みを {-1, +1} の2値に制限（※実装・派生により表現は変わりうる）
- 行列積が加算と減算中心で計算可能（[Wang et al., 2023](#ref-wang2023bitnet)）
- **幾何学的解釈:**

    - 重み空間が超立方体の頂点に制限される
    - 表現力は大幅に制限されるが、スケールや構造設計で補う

重み空間が超立方体の頂点だけになるというのは、連続空間の名残がほぼ消えることを意味する。それでもモデルが機能するのは、個々の重みの精度をスケールと構造設計で肩代わりしているからだ、というのが幾何学的な見立てである。

**1.58-bit (Ternary):**

- 重みを {-1, 0, +1} の3値に制限（[Ma et al., 2024](#ref-ma2024)）
- 0を許容することでスパース性も獲得
- **MoE（[第13回](13.md)）との接続（比喩）:** 0の重みは「その経路/寄与が消える」と解釈でき、スパース性の理解に繋がる

2値に0が一つ加わっただけの違いに見えて、この0の存在が効いている。頂点だけでなく原点も使えるようになったことで、量子化とスパース化が同じ操作の中で同時に起きる。

## 量子化誤差の幾何学的分析

量子化の仕組みがわかっても、実際にどれだけ「ずれた」かは測ってみるまでわからない。測り方は一つではなく、どこで測るかによって見える誤差の姿が変わる。

### 誤差の定量化

量子化誤差を幾何学的に測る方法：

1. **重み空間での距離:**
   $$\epsilon_w = \|\mathbf{W} - \hat{\mathbf{W}}\|_F$$
   （Frobenius ノルム）

2. **出力空間での距離:**
   $$\epsilon_y = \|f(x; \mathbf{W}) - f(x; \hat{\mathbf{W}})\|_2$$
   （特定の入力に対する出力の違い）

3. **決定境界のHausdorff距離:**
   量子化前後の決定境界がどれだけ「ずれた」かを測る

重み空間での距離が小さくても、出力空間での距離が同じように小さいとは限らない。ある層のわずかな丸め誤差が、後続の層を経由して増幅されることもあれば、吸収されて消えることもある。だとすれば、層によって量子化への耐性が違うはずだ。

### 層ごとの感度

すべての層が量子化に対して同等に頑健ではない：

- **埋め込み層:** 高感度（語彙の区別に直結）
- **Attention層:** 中程度（冗長性がある場合が多い）
- **FFN層:** 低～中（モデル/方式により異なる）
- **出力層:** 高感度（最終予測に直結）

埋め込み層と出力層が高感度、中間が相対的に頑健という並びは、直感にも合う。語彙の区別や最終予測に直結する層は、丸めのわずかなずれがそのまま意味の取り違えに化けやすい。この非一様性を逆手に取るのが、精度配分を層ごとに変える発想である。

**Mixed-Precision Quantization:**

- 感度の高い層は高精度、低い層は低精度
- **幾何学的解釈（比喩）:** 多様体の「曲率が高い」部分は細かく、「平坦な」部分は粗く

しかし、重みだけを見ていては全体の半分しか見ていないことになる。推論時に実際に流れるデータの側にも、量子化の対象は広がっている。

### 量子化は「重み」だけでは終わらない（KV cache / 活性）

LLM推論では、実務上しばしば以下が支配的になる：

- **KV cache（key/value のキャッシュ）**: 長文ではメモリ帯域や容量を圧迫し、速度/同時実行数に直結
- **アクティベーション（中間表現）**: 入力に依存して分布が変わるため、量子化の難しさが増す（キャリブレーションの重要性が上がる）

重みは学習が終われば固定される。アクティベーションはそうはいかない。入力が変わるたびに分布そのものが動くため、あらかじめ決めたキャリブレーションが外れることもある。この違いは、幾何学的に見ると位置づけがはっきりする。

**幾何学的な見方:**

- 重み量子化は「モデル側の格子化」
- 活性量子化やKV量子化は「入力により変動する軌道（表現多様体）の分解能低下」
- したがって、同じW4でも **AやKVの扱い**で体感品質が大きく変わる

重み側の格子は固定された地図であり、活性側の格子はその上を動く軌跡の解像度である。同じビット数のラベルを掲げていても、動いているものを量子化するか、止まっているものを量子化するかで難易度が違う。

## 未解決問題と研究フロンティア

既存の量子化手法がどう動くかは、ある程度追えた。しかし「なぜそこまで削っても壊れないのか」「どこまで削れば壊れるのか」という問いには、まだ確定した答えがない。

### 理論的問い

1. **量子化の限界はどこか？**

   - 何bitまで下げても性能を維持できるか？
   - 「平均性能」だけでなく「稀なケース」の破綻をどう扱うか？

2. **最適な量子化格子とは？**

   - 一様格子 vs 非一様格子
   - データ分布に適応した格子の設計
   - 幾何（球面/双曲/混合曲率）に整合した格子は作れるか？

3. **量子化とスパース性の関係**

   - MoEの各Expertを異なる精度で量子化することは有効か？
   - スパース活性化と量子化の相乗効果

理論の側が格子の設計原理を問うているのに対し、現場が抱える問いはもっと即物的である。

### 実用的課題

1. **キャリブレーションデータの選択**

   - どのデータで量子化パラメータを決定するか
   - ドメイン外データへの汎化

2. **推論時の動的量子化**

   - 入力に応じて精度を変える
   - 「簡単な」入力は低精度、「難しい」入力は高精度
   - ただしスループット/レイテンシの目標次第で有利不利が変わる

3. **学習との統合**

   - QATのさらなる改善
   - 量子化を前提としたアーキテクチャ設計
   - KV cache / 活性まで含めた最適化

## まとめ：量子化の幾何学

冒頭に置いた疑問に戻る。連続空間で学習された重みを、なぜ数個の値へ押し込めても崩れないのか。答えの一端は、量子化という射影の性質そのものにある。量子化は重み一つ一つに独立に効く丸めであり、その影響は過剰パラメータ化と冗長性に支えられて多くの場合には平均化・相殺される。しかし、この「壊れなさ」は一様ではない。稀な入力パターン、1-2 bit級の極端な圧縮、層ごとの感度の違い、球面のような制約付き多様体では、崩れ方がまだら模様になって現れる。多様体という言葉を使うなら、量子化は多様体を消すのではなく、その分解能を場所ごとに不揃いに落とす操作だと言える。

この不揃いさをどう制御するかが、GPTQやAWQのような手法の実質であり、1.58-bitのような極端な設定がなぜ機能するのかという問いの核心でもある。表現力の余剰がどこにどれだけ眠っているかを突き止めない限り、「何bitまで削れるか」という問いに一般的な答えは出せない。この点は、講義本編の各所とつながっている。

### 基本的な量子化（PyTorch・概念例）

<details>
<summary>コード例: appendix1_symmetric_quantization.py</summary>

```appendix1_symmetric_quantization.py
import torch


def quantize_tensor_symmetric(x, bits=8, eps=1e-8):
    """対称量子化の概念例（スカラーscale）。
    実務では per-channel / group-wise がよく使われる。
    """
    qmin, qmax = -(2 ** (bits - 1)), 2 ** (bits - 1) - 1
    scale = x.abs().max().clamp_min(eps) / qmax
    x_q = torch.round(x / scale).clamp(qmin, qmax)
    return x_q, scale


def dequantize_tensor(x_q, scale):
    return x_q * scale


# 使用例
weight = torch.randn(768, 768)
weight_q, scale = quantize_tensor_symmetric(weight, bits=4)
weight_approx = dequantize_tensor(weight_q, scale)
print(f"平均絶対誤差: {(weight - weight_approx).abs().mean():.6f}")
```

</details>

### 量子化前後の表現の可視化（注意付き）

数値誤差は測れても、表現空間の変形が「どんな形」をしているかは数値だけでは見えにくい。次元削減して眺めてみる。

> [!CAUTION]
> `get_hidden_states` はモデル実装に依存する（フックで取得する等が必要）。
> また t-SNE は局所構造を強調しやすく、距離の解釈には注意。

<details>
<summary>コード例: appendix1_quantization_visualization.py</summary>

```appendix1_quantization_visualization.py
import matplotlib.pyplot as plt
import torch
from sklearn.manifold import TSNE


def visualize_quantization_effect(hidden_orig, hidden_quant):
    """量子化前後の中間表現（テンソル）を比較する簡易例"""
    combined = torch.cat([hidden_orig, hidden_quant], dim=0)
    tsne = TSNE(n_components=2, perplexity=30)
    embedded = tsne.fit_transform(combined.cpu().numpy())

    n = len(hidden_orig)
    plt.scatter(embedded[:n, 0], embedded[:n, 1], label="Original", alpha=0.5)
    plt.scatter(embedded[n:, 0], embedded[n:, 1], label="Quantized", alpha=0.5)
    plt.legend()
    plt.title("Representation Space: Original vs Quantized")
    plt.show()
```
