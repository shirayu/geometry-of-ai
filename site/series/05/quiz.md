# 第5回 理解度チェック：分類の再統一 II

## マージンの幾何学

### Q1. サポートベクターマシン（SVM: Support Vector Machine）のマージン

サポートベクターマシン（SVM: Support Vector Machine）の最大マージン原理が選ぶ境界として、正しいものはどれか。

```quiz
- [x]最小距離を、制約違反のコストと調整して最大化する境界
  R: ハードマージンSVMは境界に最も近い訓練例までの距離を最大化し、ソフトマージンSVMではさらに制約違反を許すコストとのトレードオフを調整しながらゆとりを確保する。
- 制約違反を許さず、訓練例との距離を無視して重心の中間を境界とする
  R: SVMが最大化するのは境界から最近傍の訓練例までの距離そのものであり、重心の中間位置を機械的に選ぶわけではない。
- クラスの重心から最も遠い境界
  R: マージンを決めるのは境界に最も近いサポートベクターであり、重心からの距離を基準に境界を選ぶ発想ではない。
- 確率が一様になる境界
  R: SVMはヒンジ損失に基づく幾何学的な距離の最大化問題であり、確率分布の一様性を基準に境界を定めるものではない。
S: /series/05#マージンとは何か-最も「ゆとり」のある境界線
A: ハードマージンSVMでは、境界に最も近い訓練例までの距離を最大化する。ソフトマージンSVMでは、制約違反を許すコストとのトレードオフを含めて、境界からのゆとりを確保する。
```

### Q2. サポートベクター

サポートベクターの役割として、適切な説明はどれか。

```quiz
- 推論時に新しく生成されるデータ点
  R: サポートベクターは訓練時に境界を支える訓練例そのものであり、推論時に新たに生成される点ではない。
- 各クラスの重心にある訓練例
  R: サポートベクターは境界近くに位置する例であり、クラスの重心付近にある例とは位置的に対極にある。
- [x]境界近くでマージンを決める訓練例
  R: 最大マージンの境界は境界に近い訓練例の位置に強く制約されるため、境界を両側から支える支柱となる例がサポートベクターである。
- 学習から除外される外れ値を指す
  R: サポートベクターは境界の位置を決定する重要な例であり、学習から除外される対象ではなく、むしろ最適解に直接寄与する点である。
S: /series/05#マージンを決定する「支柱」-サポートベクター
A: 最大マージンの境界は、境界に近い例の位置に強く制約される。そのため、すべての訓練例ではなく、支柱となる例が境界を決める。
```

### Q3. 球面上のマージン

表現と分類重みを正規化して球面上で分類する場合、マージンは主に何を調整するか。

```quiz
- クラス確率の総和
  R: 球面上のマージンは角度方向の分離を強める幾何学的な量であり、確率の総和はSoftmaxの正規化によって常に一定なので調整対象にはならない。
- [x]角度に基づくクラス間の余裕
  R: ノルムを揃えると内積のスケール差が抑えられ、分類境界を角度として解釈できるようになるため、マージンは角度方向の分離を強める役割を持つ。
- 入力データの個数
  R: マージンは境界と表現の幾何学的な位置関係を調整する量であり、データセットに含まれる入力データの個数とは無関係である。
- 各ベクトルのノルムを無制限に大きくする量
  R: 球面上の設計ではベクトルは単位ノルムに正規化されており、マージンはノルムを大きくする量ではなく角度方向の余裕を調整する量である。
S: /series/05#空間を変えると何が変わるか
A: ノルムを揃えると内積のスケール差が抑えられ、分類境界を角度として解釈しやすくなる。マージンは角度方向の分離を強める役割を持つ。
```

### Q4. ArcFace（角度マージン分類法）のアイデア

ArcFace（角度マージン分類法）が導入するマージンの特徴はどれか。

```quiz
- 各クラスのノルムを異なる値に学習させる
  R: ArcFaceは特徴と重みを正規化した上で角度にマージンを課す設計であり、クラスごとにノルムを異なる値に学習させる仕組みではない。
- ユークリッド距離を使って角度を無視する
  R: ArcFaceは正規化された特徴と重みの内積をコサイン類似度として扱い、角度そのものにマージンを課す設計であって、角度を無視するものではない。
- 正解クラスの確率を学習前に1へ固定する
  R: ArcFaceは学習を通じて正解クラスの確率を高めるよう最適化する枠組みであり、学習前に確率をあらかじめ1に固定するものではない。
- [x]正解クラスの角度に加法マージンを課す
  R: ArcFaceは正解クラスの角度 $\theta_y$ に固定のマージン $m$ を加えることで、正解方向により厳しい条件を課し、球面上でのクラス間分離を強化する。
S: /series/05#arcfaceのアイデア
A: ArcFaceは正解クラスの角度にマージンを加えることで、正解方向をより厳しい条件で近づける。球面上のクラス間分離を明示的に強化する設計である。
```

## 手法を比較する

### Q5. 角度マージン手法の違い

ArcFace（角度マージン法）、CosFace（コサインマージン法）、SphereFace（乗法的角度マージン法）の説明として、最も妥当なものはどれか。

```quiz
- [x]角度・コサイン分離を強めるが、マージンの入れ方が異なる
  R: 三手法は角度中心の分類という考えを共有する一方、角度への加算（ArcFace）、コサインへの減算（CosFace）、角度への乗算（SphereFace）とマージンの実装方法が異なる。
- SVMとは無関係な確率モデルとして定式化されている
  R: 三手法はいずれもSoftmaxベースの分類器に角度マージンを組み込む設計であり、クラス間の分離を強める点でSVMの最大マージン原理と発想を共有している。
- 式は実質的に同じで、名前が異なる
  R: $\cos(m\theta)$、$\cos\theta - m$、$\cos(\theta + m)$ のようにマージンを課す数式の形自体が三手法で異なっており、名称だけの違いではない。
- ノルムの学習を中心にクラスを分ける手法である
  R: 三手法は特徴や重みを正規化した上で角度・コサイン空間でのマージンを課す設計であり、ノルムそのものを学習してクラスを分けるわけではない。
S: /series/05#マージンの種類-arcface、cosface、sphereface
A: これらの手法は角度中心の分類という共通した考えを持つ。一方、角度への加法やコサインへの加法など、マージンの実装方法は異なる。
```

### Q6. SVMとArcFace

SVMとArcFaceの関係について、適切な説明はどれか。

```quiz
- ArcFaceはSVMの双対問題をそのまま解いている
  R: SVMは特徴表現を固定した前提でのヒンジ損失の凸最適化問題を双対問題として解くのに対し、ArcFaceは特徴表現と境界を同時に学習する非凸なSoftmax損失の勾配降下であり、同じ双対問題を解いているわけではない。
- 最大の余裕を求める精神も最適化問題の構造も同一で、実質的に同じ手法である
  R: 両者はクラス間に余裕を持たせる発想は共有するが、SVMの凸最適化とArcFaceの勾配降下では問題の構造そのものが異なる。
- [x]最大の余裕を求める精神は共通するが、最適化問題と分類器の構造は異なる
  R: 両者はクラス間の境界に余裕を持たせる発想を共有する一方、SVMは特徴表現を固定した凸最適化、ArcFaceは特徴表現と境界を同時学習する勾配降下であり、問題の構造は異なる。
- 両者は同じ損失関数を使うため区別できない
  R: SVMはヒンジ損失、ArcFaceはSoftmaxクロスエントロピーに角度マージンを組み込んだ損失を使っており、使用する損失関数自体が異なる。
S: /series/05#共通する精神
A: 両者はクラス間の境界に余裕を持たせる発想を共有する。しかし、SVMは古典的なマージン最適化、ArcFaceはニューラル分類器に組み込む角度マージンであり、問題の構造は同じではない。
```

### Q7. 確率と幾何

ArcFaceを確率モデルか幾何モデルかのどちらか一方に限定しない説明はどれか。

```quiz
- 確率を使わず、境界を決める手法である
  R: ArcFaceの損失はSoftmaxとクロスエントロピーの形をしており、出力は確率として解釈できるため、確率を使わない手法とは言えない。
- 幾何を使わず、クラス頻度から確率を決める
  R: ArcFaceは角度マージンという幾何学的な制約をロジット設計に明示的に組み込んでおり、クラス頻度のみに基づいて確率を決めているわけではない。
- [x]Softmaxの確率出力に角度マージンを加える
  R: ArcFaceは損失関数としてはSoftmaxとクロスエントロピーに属する統計的な枠組みでありながら、ロジット設計に角度マージンという幾何学的な制約を明示的に導入しており、両方の性格を併せ持つ。
- 角度マージンを入れると確率解釈は失われる
  R: 角度マージンを加えたロジットも最終的にはSoftmaxを通じて確率として出力されるため、マージンの導入によって確率解釈そのものが失われるわけではない。
S: /series/05#arcfaceによる統計-確率-と幾何-マージン-の統合
A: ArcFaceは分類確率を出力する枠組みに、正規化された特徴と角度マージンを組み込む。統計的な出力と幾何的な分離を接続する設計と見なせる。
```

### Q8. 数値安定性

ArcFaceの学習で、正規化後の内積がごくまれに1.0000001になり、損失がNaNになった。最初に確認・修正すべきことはどれか。

```quiz
- [x]内積をクリップし、角度とSoftmaxを安定化する
  R: 正規化ベクトルの内積は理論上$[-1,1]$の範囲に収まるはずだが丸め誤差でわずかに外れることがあり、`torch.acos`の勾配発散を避けるためにも定義域へのクリップと安定した計算経路の確認が原因に即した対処になる。
- マージンを大きくして、丸め誤差を損失へ吸収させる
  R: マージンの大きさは正解クラスの角度に課すハンディキャップを変える設計上のパラメータであり、内積が定義域をわずかに外れる丸め誤差の問題そのものを解決する手段ではない。
- 正規化を外してノルムの差を角度へ含める
  R: 正規化を外すと内積が単純なコサイン類似度でなくなり角度としての解釈が崩れるため、数値誤差の問題を解決するどころか設計の前提を壊してしまう。
- NaNが出たバッチを除外し、学習率や入力分布は調べない
  R: NaNが出たバッチを除外するだけでは丸め誤差によって内積が定義域を外れるという原因そのものは残り続け、同じ問題が別のバッチで再発しうる。
S: /series/05#数値安定なarcface
A: 正規化ベクトルの内積は理論上の範囲を丸め誤差で外れることがある。定義域へのクリップと安定した指数計算を確認し、原因を隠す変更は避ける。
```
