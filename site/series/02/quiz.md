# 第2回 理解度チェック：ノルムの呪い

選択肢をクリックすると、その場で正誤と解説が表示される。

「必須」は、次回（第3回：プラネタリウムの建設）を読み進める前提として押さえておきたい項目。「発展」は余裕があれば。

## 必須

### Q1. ノルムの三重の意味

深層学習初期のベクトル表現において、「ノルム」という一つの数値に混在していた3つの意味の組み合わせとして正しいものはどれか。

```quiz
- [x]意味の強度、モデルの確信度、スケーリングノイズ
- 意味の強度、学習率、正則化係数
- 頻度、次元数、バッチサイズ
- 確信度、勾配のノルム、学習率
A: 本文「三重の意味」の表を参照。この3つが同じ数値に混在していたことが、章全体の出発点になっている。
```

### Q2. 距離の集中

高次元空間（各成分が独立同分布のランダムベクトル）において、次元 d が大きくなるほど原点からの距離はどうなるか。

```quiz
- 距離の相対的なばらつきが大きくなる
- [x]距離が期待値 √d 付近に集中し、相対的なばらつきは0に近づく
- すべての点が原点に集まる
- 距離が定義できなくなる
A: E[r²] = d で、r² の変動係数は √(2/d) → 0。「距離が集中する」＝「みんな同じくらい遠い」ことで、近傍探索の手がかりが失われる。
```

### Q3. 直交性の祝福

高次元空間でランダムに選んだ二つのベクトルがほぼ直交することは、なぜ「呪い」ではなく「祝福」にもなりうるのか。

```quiz
- 直交するベクトルは計算コストが低いから
- [x]ほぼ直交するベクトルを大量に配置でき、独立な表現を多数詰め込めるから
- 直交すれば距離が近くなるから
- 直交性はノルムの問題を自動的に解決するから
A: 「互いに干渉しない」方向を高次元空間には大量に確保できる。ただし本文にもある通り、これは必要条件であって十分条件ではない（意味構造を作るには学習が必要）。
```

### Q4. 次回への接続

第2回で提示された「ノルムの呪い」への一つの回答として、第3回で導入される設計方針はどれか。

```quiz
- ノルムを学習可能なパラメータとして各層ごとに最適化する
- ノルムを完全に削除し、方向情報も破棄する
- [x]ノルムを定数に固定し、向き（方向）だけを自由度として残す（球面上での計算）
- ノルムとロジットのスケールを別々のネットワークで学習する
A: 「捨てるのではなく、定数に固定して向きだけを自由度にする」という発想が第3回の主題。ここが曖昧なまま進むと、以降の「角度中心の設計」全体の動機が見えなくなる。
```

## 発展

### Q5. ハブ化問題

正規化しない表現で内積（ノルムの積 × 方向の類似度）を類似度として使うと、なぜ「ハブ化」が起きるか。

```quiz
- [x]ノルムが大きいベクトルが、無関係な相手との内積も大きくなりやすいから
- 内積の計算がO(d²)になるから
- コサイン類似度が定義できなくなるから
- 高次元では内積が常に0になるから
A: ノルムが大きいベクトル（例：高頻度語）が、方向に関わらず内積を押し上げてしまい、無関係なクエリでも上位に出現する。
```

### Q6. カプセルネットワークの位置づけ

カプセルネットワークが「向きと長さの分離」を明示的に試みたにもかかわらず、実用的に広く普及しなかった理由として本文が挙げていないものはどれか。

```quiz
- 動的ルーティングによる計算コストの増大
- ImageNetのような大規模データセットへのスケーラビリティの困難
- [x]理論的に誤りがあることが証明されたため
- 大規模ベンチマークでCNNやTransformerに対する優位性が限定的だったこと
A: 本文はカプセルネットワークの限界を計算コスト・スケーラビリティ・実用性能の面から説明しており、「理論的誤り」とはしていない。「向きと長さの分離」という問題提起自体は後続手法にも影響しうるとされる。
```
