# Appendix 3 理解度チェック：動的剪定の幾何学

## 選択的な計算

### Q1. 静的と動的な回路

静的な回路と動的な回路の違いとして、正しいものはどれか。

```quiz
- [x]入力ごとに計算経路が変わるかで異なる
  R: 静的な回路は入力に依存しない固定された計算経路を持つのに対し、動的な回路はAttentionのように入力自身が経路や重み付けを決定する点で異なる。
- 動的な回路は各層のゲートを学習ではなく乱数で決めるため重みの更新対象にならない
  R: 動的な回路のゲートやAttentionの重みは、Query・KeyやルーターのようにQueryやパラメータから計算され、通常のパラメータと同様に学習によって更新される対象である。
- 静的な回路は誤差逆伝播の経路が一意に定まるため、動的な回路より学習が安定する
  R: 静的か動的かという区別は計算経路が入力に依存するかどうかの違いであり、誤差逆伝播の経路の一意性や学習の安定性そのものを直接決める性質ではない。
- 両者は入力の内容にかかわらず、割り当てる計算資源の配分方針が同じである
  R: 動的な回路はAttentionのパターンのように入力の内容に応じて情報の流れや資源配分を変化させる点が、入力に依存しない静的な回路との本質的な違いである。
S: /series/appendix.3#transformer以降の「動的性」
A: 動的性は、入力に応じてAttentionの参照先やExpertなどを選ぶ性質である。必要な計算へ資源を配分できる一方、ルーティングの安定性が課題になる。
```

### Q2. Attentionの剪定

Attentionをミクロな動的剪定と見る理由はどれか。

```quiz
- Attentionは重みを学習しないから
  R: Attentionの重みはQueryとKeyの内積とSoftmaxから入力ごとに計算される値であり、学習されたパラメータを通じて間接的に決まる。重みを学習しないという説明は成り立たない。
- 各トークン間の情報を同じ強さで使うから
  R: Softmax後の重みは接続ごとに異なる値を取り、有意な重みを持つ接続だけが実質的な影響力を持つため、すべての接続を同じ強さで使うわけではない。
- Attentionは層全体を削除するから
  R: Attentionは全結合グラフの接続を計算したうえで重みを小さくする情報的剪定であり、層そのものを削除する操作ではない。
- [x]入力ごとに重みが変わり、有意な接続が相対的に残るから
  R: Attention scoreは入力ごとに計算され、Softmax後は有意な重みを持つ接続の影響が相対的に大きくなるため、実質的に重要でない接続を弱めるソフトな剪定と見なせる。
S: /series/appendix.3#全結合からの選択的遮断
A: Attentionは内積とSoftmaxによって参照強度を入力ごとに変える。有意な重みを持つ接続の影響が相対的に大きくなるため、重要でない接続を実質的に弱めるソフトな剪定と見なせる。ただし、計算を完全に省くとは限らない。
```

### Q3. MoE（Mixture of Experts、専門家混合）のルーティング

MoE（Mixture of Experts、専門家混合）をマクロな部分空間スイッチングと見る説明はどれか。

```quiz
- MoEは表現空間を使わずにルーティングする
  R: MoEのルーターは入力ベクトルとゲートベクトルの内積によってExpertを選ぶため、表現空間そのものを使ってルーティングを行っている。
- 各Expertを同じ重みで実行する
  R: MoEはTop-K選択されたExpertそれぞれにルーティング確率に応じた異なる重みを掛けて加重和を取るため、すべてのExpertを同じ重みで実行するわけではない。
- Expertは入力に依存せず固定の出力を返す
  R: 各Expertは入力ベクトルを受け取って計算するネットワークであり、出力は入力に応じて変化する。固定の出力を返すわけではない。
- [x]入力ごとに少数のExpertを選び、計算を切り替える
  R: MoEのルーターは入力ごとにゲート値を計算し、Top-Kで選ばれた少数のExpertだけを活性化するため、入力に応じて計算を切り替える部分空間スイッチングと見なせる。
S: /series/appendix.3#部分空間スイッチングとしてのmoe-仮説的解釈
A: MoEのゲートは入力ごとにExpertを選ぶため、表現空間の領域に応じて計算を切り替える見方ができる。ただし、部分空間という解釈は仮説的である。
```

### Q4. Routing Collapse

Routing Collapseが起きると、何が問題になるか。

```quiz
- [x]一部のExpertに集中し、容量超過や未使用が生じる
  R: Routing Collapseはトークンが同じExpertに集中する現象であり、集中したExpertは容量超過に、他のExpertは未使用のまま負荷が偏る問題を引き起こす。
- Expertが均等に使われ、計算が効率化する
  R: Routing Collapseはむしろ特定のExpertに負荷が集中し他のExpertがほとんど使われなくなる現象であり、均等な利用による効率化とは逆の状態を指す。
- 各Expertが同じ専門性を持つ
  R: Routing Collapseは負荷の偏りに関する現象であり、Expertが同じ専門性を持つかどうかという専門化の程度そのものを直接述べたものではない。
- ルーティングの結果が入力から独立する
  R: Routing Collapseはルーターが入力によらず特定のExpertを選び続けてしまう偏りの問題であり、ルーティングの計算自体が入力から独立するわけではない。
S: /series/appendix.3#moeの課題-ルーティング崩壊-routing-collapse
A: ゲートが一部のExpertを選び続けると、負荷の偏りや専門化の崩れが起きる。補助損失、容量制約、ルーティング規則などで対処する。
```

## 疎性と効率化

### Q5. スパース化の条件

スパース化が有効になる条件として、最も適切なものはどれか。

```quiz
- パラメータ数さえ削減できれば、削る対象や配置は結果に影響しない
  R: スパース化の有効性は信号対雑音比やタスクの要求などの条件に依存しており、何をどこで削るかという対象や配置が結果を左右する。
- [x]省ける計算と許容できる損失がある
  R: スパース化が有効になるのは、無関係な次元をノイズとして除外できる、あるいは性能を落とさずに計算を省ける条件が揃った場合であり、削れる計算と許容できる損失の両方が鍵になる。
- スパース化の速度向上はアルゴリズム上の理論値で決まり、実装や実行環境の影響は小さい
  R: スパース化による速度向上はハードウェアや実装形式に強く依存し、疎にすれば理論値通りに常に速くなるわけではない。
- スパース化は情報を圧縮して保持するため、密な計算より表現できる情報が増える
  R: スパース化は無関係な次元を除外する操作であり、条件によっては必要な情報まで失われうる。密な計算より表現できる情報が増えるとは限らない。
S: /series/appendix.3#スパース化の有効性-条件依存
A: 疎性は計算量削減の手がかりになるが、信号対雑音比、タスク、ハードウェア、実装形式に依存する。疎にすれば常に速くなるわけではない。
```

### Q6. GQA（Grouped-Query Attention）、LoRA（Low-Rank Adaptation）、MoD（Mixture-of-Depths）

GQA（Grouped-Query Attention）、LoRA（Low-Rank Adaptation）、MoD（Mixture-of-Depths）に共通する設計思想はどれか。

```quiz
- 各計算を増やして表現を密にする
  R: GQAはKVヘッドの共有、LoRAは更新の低ランク化、MoDは層のスキップにより計算や更新を削減する設計であり、計算を増やして密にする方向とは逆である。
- いずれもルーティングをランダムにする
  R: MoDのようなトークンごとの層の通過は学習されたゲートに基づいて決まるものであり、GQAやLoRAはそもそもルーティングという仕組みを持たない設計上の削減である。
- いずれも同じアルゴリズムでKey-Value cache（KV cache）を量子化する
  R: KVキャッシュの削減に関わるのはGQAのヘッド共有であり、LoRAは重み更新の低ランク化、MoDは層の通過制御という異なる仕組みで冗長性を減らしている。
- [x]冗長な計算や更新を構造的に減らし、必要な部分へ資源を集中する
  R: GQAはKey-Valueの共有、LoRAは更新の低ランク化、MoDは深さ方向の計算選択によって、それぞれ異なる対象の冗長性を削り必要な部分に資源を集中させるという共通の設計思想を持つ。
S: /series/appendix.3#統一的整理
A: GQAはKey-Value（KV）の共有、LoRAは更新の低ランク化、MoDは深さ方向の計算選択に関わる。実装は異なるが、冗長性を削って効率化する共通の見方ができる。
```

### Q7. FlashAttention（メモリ入出力を削減するAttention実装）

FlashAttention（メモリ入出力を削減するAttention実装）の主な工夫はどれか。

```quiz
- [x]タイル化・再計算でI/Oを減らす
  R: FlashAttentionは行列をタイルに分割してSRAMで計算し、逆伝播時には中間結果を再計算することで、HBMとSRAM間のI/O回数を削減する設計である。
- 各中間行列をGPUメモリへ保存する
  R: FlashAttentionはむしろ中間結果をHBMに保存せず必要な時に再計算する戦略を取っており、これによってメモリへの書き込みと読み出しを削減している。
- Attentionの結果を近似的にランダム化する
  R: FlashAttentionは数学的に等価な結果を保ったままメモリアクセスパターンを最適化する手法であり、計算結果を近似したりランダム化したりするものではない。
- Attentionのヘッドを削除する
  R: FlashAttentionはメモリ階層に合わせた計算順序の工夫であり、Attentionのヘッド数や構造自体を削減する手法ではない。
S: /series/appendix.3#flashattentionの仕組み-i-o削減と再計算戦略
A: FlashAttentionはAttentionの式を近似して意味を変えるのではなく、メモリ階層に合わせた計算順序と再計算でI/Oを削減する。
```

### Q8. 動的剪定と知能

動的剪定で平均レイテンシは下がったが、長い入力の一部で品質が落ちた。次の評価として、最も適切なものはどれか。

```quiz
- [x]入力分布・品質・尾部レイテンシを分けて比較する
  R: 動的剪定の価値は平均速度だけでは判断できず、入力分布ごとの品質、尾部レイテンシ、ルーティングの負荷などを分けて確認することで、長い入力での品質低下のような問題を見つけられる。
- 削る計算量を増やし、品質低下はモデル容量で吸収する
  R: 品質低下の原因を確認しないまま計算削減量を増やすと、長い入力での問題をさらに悪化させかねず、モデル容量を増やすだけでは根本的な評価にならない。
- 平均レイテンシだけを採用し、入力長別の品質は測らない
  R: 平均レイテンシだけを見ていては、長い入力の一部で品質が落ちるという偏った問題を見逃してしまい、入力長別の品質確認が欠かせない。
- 動的剪定の評価を、密なモデルのパラメータ数だけで決める
  R: パラメータ数は動的剪定が実際にどの入力でどれだけ品質やレイテンシに影響するかを反映しておらず、それだけで評価を決めるのは不十分である。
S: /series/appendix.3#「何を計算しないか」を決める知能
A: 動的剪定の価値は平均速度だけでは決まらない。入力別の品質、尾部レイテンシ、ルーティングの負荷、対象ハードウェアを併せて評価する必要がある。
```
