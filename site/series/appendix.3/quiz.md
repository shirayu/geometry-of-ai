# Appendix 3 理解度チェック：動的剪定の幾何学

## 選択的な計算

### Q1. 静的と動的な回路

静的な回路と動的な回路の違いとして、正しいものはどれか。

```quiz
- [x]静的な回路は入力によらず経路が固定され、動的な回路は入力に応じて計算経路を変える
- 静的な回路だけが学習可能である
- 動的な回路は重みを持たない
- 両者は入力ごとの計算量が必ず同じである
S: /series/appendix.3#transformer以降の「動的性」
A: 動的性は、入力に応じてAttentionの参照先やExpertなどを選ぶ性質である。必要な計算へ資源を配分できる一方、ルーティングの安定性が課題になる。
```

### Q2. Attentionの剪定

Attentionをミクロな動的剪定と見る理由はどれか。

```quiz
- すべてのトークン間の情報を必ず同じ強さで使うから
- [x]Query-Keyの関係に基づいて、入力ごとに参照の重みを変えるから
- Attentionは層全体を削除するから
- Attentionは重みを学習しないから
S: /series/appendix.3#全結合からの選択的遮断
A: Attentionは内積とSoftmaxによってトークン間の参照強度を入力ごとに変える。計算を完全に省くとは限らないが、情報の流れを選択的に制御する。
```

### Q3. MoEのルーティング

MoEをマクロな部分空間スイッチングと見る説明はどれか。

```quiz
- [x]入力に応じて少数のExpertを選び、異なる専門領域の計算を切り替える
- すべてのExpertを常に同じ重みで実行する
- Expertは入力に依存せず固定の出力を返す
- MoEは表現空間を使わずにルーティングする
S: /series/appendix.3#部分空間スイッチングとしてのmoe-仮説的解釈
A: MoEのゲートは入力ごとにExpertを選ぶため、表現空間の領域に応じて計算を切り替える見方ができる。ただし、部分空間という解釈は仮説的である。
```

### Q4. Routing Collapse

Routing Collapseが起きると、何が問題になるか。

```quiz
- Expertが均等に使われ、計算が必ず効率化する
- すべてのExpertが同じ専門性を持つ
- [x]一部のExpertに入力が集中し、容量超過や未使用Expertが生じる
- ルーティングの結果が入力から独立する
S: /series/appendix.3#moeの課題-ルーティング崩壊-routing-collapse
A: ゲートが一部のExpertを選び続けると、負荷の偏りや専門化の崩れが起きる。補助損失、容量制約、ルーティング規則などで対処する。
```

## 疎性と効率化

### Q5. スパース化の条件

スパース化が有効になる条件として、最も適切なものはどれか。

```quiz
- [x]不要な計算を省ける構造があり、削減による情報損失と実装コストが許容範囲に収まる
- 次元が高ければ、どんな計算でも削ればよい
- スパース化すると情報は必ず増える
- ハードウェアやメモリ階層は関係しない
S: /series/appendix.3#スパース化の有効性-条件依存
A: 疎性は計算量削減の手がかりになるが、信号対雑音比、タスク、ハードウェア、実装形式に依存する。疎にすれば常に速くなるわけではない。
```

### Q6. GQA・LoRA・MoD

GQA、LoRA、MoDに共通する設計思想はどれか。

```quiz
- すべての計算を増やして表現を密にする
- [x]冗長な計算や更新を構造的に減らし、必要な部分へ資源を集中する
- いずれも同じアルゴリズムでKV cacheを量子化する
- いずれもルーティングをランダムにする
S: /series/appendix.3#統一的整理
A: GQAはKVの共有、LoRAは更新の低ランク化、MoDは深さ方向の計算選択に関わる。実装は異なるが、冗長性を削って効率化する共通の見方ができる。
```

### Q7. FlashAttention

FlashAttentionの主な工夫はどれか。

```quiz
- Attentionの結果を近似的にランダム化する
- すべての中間行列をGPUメモリへ保存する
- [x]GPUメモリ階層を意識し、タイル化と再計算でメモリI/Oを減らしながら厳密計算する
- Attentionのヘッドをすべて削除する
S: /series/appendix.3#flashattentionの仕組み-i-o削減と再計算戦略
A: FlashAttentionはAttentionの式を近似して意味を変えるのではなく、メモリ階層に合わせた計算順序と再計算でI/Oを削減する。
```

### Q8. 動的剪定と知能

動的剪定を知能の設計として評価するとき、妥当な説明はどれか。

```quiz
- 削らない計算が多いほど必ず知能が高い
- [x]何を計算しないかを入力に応じて選ぶことが、抽象化や効率的な推論につながりうる
- 動的選択を導入すれば誤りは必ずなくなる
- 剪定の有効性はタスクや入力分布に依存しない
S: /series/appendix.3#「何を計算しないか」を決める知能
A: 動的剪定は、すべてを一様に計算せず、入力にとって必要な部分へ資源を割り当てる考え方である。性能と効率の評価はタスク依存である。
```
