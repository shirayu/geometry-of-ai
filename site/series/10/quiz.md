# 第10回: 思考の連鎖: 推論の軌跡（理解度チェック）

## 推論を経路として見る

### Q1. One-shotとMulti-step

One-shot推論とMulti-step推論の違いとして、適切な説明はどれか。

```quiz
- 両者は中間表現の有無に違いがない
  R: One-shotは質問から答えへの直接的なマッピングであり、Multi-stepは中間ステップという「足場」の表現を経由する点で、中間表現の有無そのものが両者を分ける違いである。
- [x]直接答えるか、中間段階で問題を分解するかの違い
  R: One-shotは短い直接経路で答えに至り、Multi-stepは中間の「足場」を経由しながら問題を小さな段階へ分解して進む点で異なる。
- Multi-stepでは計算量が増えない
  R: 中間ステップを生成する分だけ出力トークン数が増えるため、Multi-stepは計算量が増える方向に働く。
- One-shotは正しく、Multi-stepは誤る
  R: どちらが適切かは問題の複雑さに左右され、単純な問題ではOne-shotで十分だが複雑な問題ではMulti-stepが有効になるなど、一方が常に正しいという関係ではない。
S: /series/10#multi-step推論-足場を使った旅
A: Multi-step推論は中間の足場を使うことで、問題を小さな段階へ分けられる。計算量や誤りの蓄積が増えるため、常に有利とは限らない。
```

### Q2. Chain of Thought（CoT、思考の連鎖）

Chain of Thought（CoT、思考の連鎖）の本質を説明したものはどれか。

```quiz
- 推論時の計算を一回に制限する
  R: CoTは中間ステップを段階的に出力する技術であり、推論を一回の計算に制限するものではなく、むしろ複数段階に分けて計算を進める。
- 最終回答を短く出力する
  R: CoTは最終回答だけでなく、その前に中間ステップを明示的に出力する点が特徴であり、短い最終回答のみを出す方法とは逆の発想である。
- モデル内部の連続状態の軌道をそのまま観測する
  R: 中間トークンはSoftmaxを通じて連続的な隠れ状態から離散的な単語へ変換された結果であり、内部の連続状態の軌道そのものを直接観測しているわけではない。
- [x]中間トークンを足場にして段階的に推論する
  R: CoTは中間的な言語トークンを足場として出力しながら、連続的な思考過程を段階的に進める技術として解釈できる。
S: /series/10#cotとは何か
A: CoTは中間的な言語トークンを通じて推論段階を表す。ただし、出力されたテキストが内部で実際に行われた計算を完全に反映するとは限らない。
```

### Q3. Test-time Compute Scaling

推論時の計算量を増やす方法として、適切なものはどれか。

```quiz
- モデルの隠れ層の幅を広げてから推論する方法
  R: 隠れ層の幅は学習前に決めるモデル構造の一部であり、学習済みの重みを固定したまま推論時の計算を追加するTest-time compute scalingとは異なる。
- 学習データを増やして再学習し、推論に備える方法
  R: 学習データの増加は学習時のスケーリングに属し、訓練済みのモデル重みを固定したまま推論時の計算を増やすTest-time compute scalingとは対象が異なる。
- 推論時のバッチサイズを大きくして計算量を増やす方法
  R: バッチサイズの変更は同時に処理する入力の数を増やすスループットの操作であり、個々の入力に対する推論の計算（生成トークン数、試行回数、探索幅等）を増やすTest-time compute scalingとは異なる。
- [x]推論時の生成や探索に計算を追加する
  R: シーケンス長の拡張、サンプリング回数の増加、探索アルゴリズムの適用、検証と修正といった手法はいずれも、学習済みの重みは変えずに推論時の生成や探索にかける計算を増やすものである。
S: /series/10#計算量を増やす方法-分類
A: Test-time scalingには、長い推論、複数試行、木探索、検証と修正などがある。増やす計算の対象によって効果やコストは異なる。
```

### Q4. HMM（Hidden Markov Model、隠れマルコフモデル）との対比

HMM（Hidden Markov Model、隠れマルコフモデル）とTransformerによるCoTの対比として、適切な説明はどれか。

```quiz
- 両者は同じ確率モデルで、同じ依存構造を持つ
  R: HMMは離散状態間のマルコフ性に基づく局所遷移を仮定するのに対し、Transformerは連続表現とAttentionによる大域的な依存を扱う点で、モデルの構造そのものが異なる。
- HMMは大域的な依存を一度に扱い、局所制約を持たない
  R: HMMの中心的な仮定はマルコフ性であり、現在の状態は直前の状態のみに依存するという局所的な制約を持つため、大域的な依存を一度に扱うという説明は逆である。
- [x]HMMは局所依存、Transformerは広域参照する
  R: HMMはマルコフ性により直前の状態のみに依存する局所的な遷移構造を持つのに対し、TransformerはAttention機構によって系列全体を参照できる大域的な構造を持つ。
- Transformerは隠れ状態を持たず、出力を計算する
  R: Transformerは各トークン位置で連続的な隠れ状態（hidden states）を保持しながら層を通過させるため、隠れ状態を持たないという説明は成り立たない。
S: /series/10#transformerとcot-大域的な文脈
A: HMMの基本的な状態遷移は局所的な依存を持つ。一方、TransformerはAttentionで離れたトークン間の関係を参照できるため、広い文脈の推論を表しやすい。
```

## 探索と縮退

### Q5. ビームサーチの選択条件

デコーディング戦略の選択について、ビームサーチに関する最も適切な判断はどれか。

```quiz
- 各ステップで候補を絞り込まずに探索するため、大域的に最良の系列を見つけられる
  R: ビームサーチは各ステップで上位k個の候補に絞り込む近似的な探索であり、総当たり探索のように全経路を列挙するわけではないため、大域的な最良性は保証されない。
- ビームサーチは貪欲法の局所最適を避けられるが、候補を確率の高い経路に絞るため、多様性が欲しいタスクにも等しく適する
  R: ビームサーチは貪欲法の局所最適を避けられるが、確率の高い上位候補に絞り込む探索であるため、多様性が欲しいタスクにはTop-kサンプリングなど別の戦略の方が適している。
- [x]貪欲法の局所最適を避けられるが、ビーム幅に応じて計算量が増えるため、正確性重視のタスクかで選ぶ
  R: ビームサーチは複数の候補経路を同時に追跡することで貪欲法が陥りやすい局所最適を回避できるが、ビーム幅が大きいほど計算量が増える確実さ重視の探索であるため、翻訳など正確性が求められるタスクかどうかで採否を判断するのが妥当である。
- ビームサーチは多様な経路をサンプリングするので、創作のように多様性が欲しいタスクに向く
  R: ビームサーチは確率の高い上位候補に絞り込む確実さ重視の探索であり、多様性を求めるタスクにはTop-kサンプリングなど別の戦略の方が適している。
S: /series/10#ビームサーチ-複数経路の同時探索
A: ビームサーチは上位候補を複数保持し、貪欲法が陥りやすい局所最適に対処する。ただし、ビーム幅が大きいほど計算量は増え、確実さ重視の探索であるため、多様性が欲しいタスクではTop-kサンプリングなどの戦略が候補になる。
```

### Q6. Model Collapse

Model Collapseの説明として、正しいものはどれか。

```quiz
- モデルが訓練データに過学習し、検証精度が下がる問題
  R: Model Collapseは訓練データそのものへの過学習ではなく、モデル自身が生成したデータで世代を重ねて再学習することにより生成の多様性が失われる現象である。
- [x]生成データの再学習で分布の多様性が失われる
  R: 生成モデルが自己生成データで再学習を繰り返すと、生成データが元の分布の確率が高い領域に偏り、その偏りが世代を重ねるごとに強化されて多様性が失われていく。
- 生成データを再学習に使うことで、むしろ元の分布より多様性が高まる現象
  R: 生成データでの再学習は分布のモードへの偏りを強化する方向に働くため、多様性が高まるのではなく失われていく現象として観測される。
- モデルが訓練データを過剰に記憶する現象
  R: 訓練データへの過剰な記憶は過学習として知られる現象である。Model Collapseは訓練データそのものへの過学習ではなく、モデル自身が生成したデータで世代を重ねて再学習することにより多様性が失われる現象を指す。
S: /series/10#現象の説明
A: Model Collapseは、生成物に偏ったデータを繰り返し学習することで、元の分布にあった多様性が失われる問題である。表現の次元縮退とは別の現象である。
```

### Q7. Dimensional Collapse

Dimensional Collapseを検出する指標として、適切なものはどれか。

```quiz
- ビーム幅を増やす
  R: ビーム幅はデコーディング時の探索候補数を決めるパラメータであり、表現の有効次元がどれだけ使われているかというDimensional Collapseの検出とは無関係である。
- 生成された文章の文字数を数える
  R: 文字数は出力系列の表面的な長さにすぎず、埋め込み空間の有効次元が縮んでいるかどうかを示す指標にはならない。
- [x]表現の特異値や有効ランクを調べる
  R: 埋め込み行列を特異値分解し、特異値の減衰の仕方や有効ランクを見ることで、実質的に何次元が使われているかを定量的に調べられる。
- クラスラベルの頻度を調べる
  R: クラスラベルの頻度分布は分類タスクにおけるデータの偏りを示す指標であり、表現空間の有効次元が縮退しているかどうかとは別の観点である。
S: /series/10#検出方法-特異値分解
A: 表現の特異値が一部の方向に偏ると、有効な次元が縮む。特異値分解や有効ランクは、この縮退を量的に調べる手がかりになる。
```

### Q8. 幾何学的比喩の限界

長いCoTは短いCoTより正答率が上がるが、誤答も長くなった。この現象を調べる方針として、最も適切なものはどれか。

```quiz
- 出力の長さを増やし、途中の検証は加えない
  R: 出力を長くするだけでは誤りの蓄積を防ぐ手立てがなく、正答率の向上と誤答の増加という両方の変化が起きた原因を切り分けられない。
- CoTを滑らかな曲線として可視化し、離散的な出力の誤りを説明する
  R: 「軌跡」という見方は直感を助ける比喩であり、離散的なトークン生成の過程を文字通り連続的な軌道として扱って誤りの原因を説明する根拠にはならない。
- 長い出力は内部計算も多いとみなし、正答率で原因を決める
  R: 出力トークン数と内部で行われた計算量は必ずしも比例しないため、正答率という一つの指標だけでは長い出力がなぜ誤りも増やしたのかという原因は特定できない。
- [x]推論段階・検証・探索コスト・誤りを分けて評価する
  R: 長さと正答率の相関だけでは検証の効果と誤りの蓄積を区別できないため、出力トークン列・内部状態・探索手順といった要素を分けて評価する必要がある。
S: /series/10#幾何学的解釈-比喩
A: 長さと正答率の相関だけでは、検証の効果と誤りの蓄積を分けられない。出力トークン列、内部状態、探索手順を区別して評価する必要がある。
```
